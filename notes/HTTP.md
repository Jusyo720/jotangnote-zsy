# HTTP
## Q1
- **请求**
    - **请求行** (Request Line)：包含请求方法（如 GET、POST）、请求的 URL 路径以及 HTTP 协议版本。
    - **请求头** (Request Headers)：包含关于客户端环境和请求体信息的元数据（如 Content-Type、User-Agent、Authorization 等）。
    - **空行** (Empty Line)：用于分隔请求头和请求体。
    - **请求体** (Request Body)：可选部分，通常用于 POST 或 PUT 请求中携带要发送给服务器的数据（如表单内容、JSON 数据）。
- **响应**
    - **状态行** (Status Line)：包含 HTTP 版本、状态码（如 200、404）和状态消息（如 OK、Not Found）。
    - **响应头** (Response Headers)：包含关于服务器和响应体信息的元数据（如 Content-Type、Content-Length、Set-Cookie 等）。
    - **空行** (Empty Line)：用于分隔响应头和响应体。
    - **响应体** (Response Body)：可选部分，包含服务器返回给客户端的实际数据（如 HTML 代码、图片二进制数据、JSON 结果）。
    
## Q2
应该使用`POST`，因为在请求方法中`POST`的含义就是提交。

常见的HTTP请求方法：
- **GET（获取）**：相当于“拿取”。用于请求服务器上的资源，比如打开一个网页、下载一张图片。GET 请求不会改变服务器上的任何数据。 
- **POST（提交）**：相当于“提交”。用于向服务器发送数据，比如你填写注册表单、发表评论，或者上传文件。这通常会改变服务器上的数据（如新建一条记录）。
- **PUT（替换）**：相当于“整体更新”。用于向服务器发送数据，以替换掉原有的完整资源。
- **DELETE（删除）**：相当于“删除”。用于请求服务器删除某个指定的资源。

## Q3
- **HTTP状态码**是服务器在响应客户端请求时返回的一个**三位数字代码**，用于指示请求的处理结果和状态。
- 常见的状态码：
    -   **1xx（信息响应）**：请求已经收到，继续处理中（比如 `100 Continue`）。
    -   **2xx（成功响应）**：请求已成功被服务器接收、理解并处理。
        -   `200 OK`：最通用的成功标志，表示一切正常。
    -   **3xx（重定向）**：需要进一步操作才能完成请求。
         -   `301 Moved Permanently`：资源已被永久移动到新位置。
    -   **4xx（客户端错误）**：请求本身存在错误，服务器无法完成。
        -   `404 Not Found`：最常见的错误，表示你要访问的页面或资源找不到了。
    -   **5xx（服务端错误）**：服务器在处理请求时自己出了故障。
        -   `500 Internal Server Error`：表示服务器内部程序出现了未知的错误。
- 在开发过程中可能遇到
    - `200 OK`：**成功**。例如，用户成功获取了笔记列表，或者成功查看了一篇笔记的详情。
    - `201 Created`：**已创建**。例如，用户成功提交了一篇新笔记，服务器创建该资源后返回此状态码。
    - `400 Bad Request`：**客户端错误（参数错误）**。例如，用户提交的笔记标题为空，或者笔记内容超过了系统允许的最大长度，服务器校验不通过时返回。
    - `401 Unauthorized`：**未授权**。例如，用户未登录或登录凭证（如 Token）失效时，尝试访问受保护的笔记接口，服务器返回此状态码提示需要重新登录。
    - `403 Forbidden`：**禁止访问**。例如，用户尝试删除或修改不属于自己的笔记时，服务器进行权限校验后拒绝操作并返回此状态码。
    - `404 Not Found`：**资源未找到**。例如，用户尝试访问一篇已经被删除的笔记，或者输入了错误的 API 接口地址时返回。
    - `500 Internal Server Error`：**服务器内部错误**。例如，在处理笔记保存请求时，服务器代码抛出了未捕获的异常或数据库连接失败，导致无法正常完成请求时返回。
